# Portal layout

Import the standalone `HwPortalLayoutComponent` to get the header, optional
secondary navigation, breadcrumb, focusable main container and footer together.

```html
<hw-portal-layout lang="ar" dir="rtl" brand="هوية"
  skipLabel="انتقل إلى المحتوى" menuLabel="القائمة" navigationLabel="التنقل الرئيسي"
  secondaryLabel="التنقل الثانوي" breadcrumbLabel="مسار التنقل" footerLabel="روابط التذييل"
  externalLabel="يفتح في نافذة جديدة"
  [links]="links" [secondaryNavigation]="links"
  [breadcrumbs]="breadcrumbs" [footerLinks]="footerLinks">
  <h1>الخدمات</h1>
</hw-portal-layout>
```

```ts
links = [{ label: 'الخدمات', href: '/services', current: true }];
breadcrumbs = [{ label: 'الرئيسية', href: '/' }, { label: 'الخدمات' }];
footerLinks = [{ label: 'الخصوصية', href: '/privacy' }];
```

Inputs: `brand`, `brandLabel`, `homeHref`, `links`, `secondaryNavigation`,
`footerLinks`, `breadcrumbs`, `copyright`, `mainId`, `navigationId`, `dir`.

## Text is supplied by the application

The layout has no default text, language or direction.

- Required in every use: `skipLabel` (the layout always has a main target, so its
  skip link is always rendered), `menuLabel`, `navigationLabel` and
  `externalLabel` (screen-reader text added to footer links marked `external`).
- Required with the data that switches the part on: `secondaryLabel` with
  `secondaryNavigation`, `breadcrumbLabel` with `breadcrumbs`, `footerLabel` with
  `footerLinks`.
- A missing text renders nothing in its place and is reported once in
  development with the prefix `Hawiyah:`.
- `dir` is rendered only when it is supplied. There is no `lang` input: `lang` is
  an ordinary attribute that the application sets on `hw-portal-layout` or on
  an ancestor. Language and direction remain independent.

The brand is the application's content and may be artwork alone. `brand` is
optional plain text for the header and the footer; projected `[hwBrand]` artwork
can stand without it, and no brand text is printed unless `brand` is supplied.
`brandLabel` is written as `aria-label` on the brand link, which is how artwork
without text gets its accessible name; with visible brand text and no
`brandLabel`, nothing is added. An empty `homeHref` renders the brand without an
`href`, so it is not a link. In development, a brand with no text, no accessible
name and no image `alt` is reported after the first render in a browser.

The layout passes `brand` and `brandLabel` to its footer as well. Angular
projects a node once, so the footer does not repeat the `[hwBrand]` artwork:
project a second copy as `[hwFooterBrand]` content, which `brandLabel` then
names. Without brand text or footer artwork the footer brand block stays empty
and unnamed.

```html
<hw-portal-layout brandLabel="هوية، الصفحة الرئيسية" skipLabel="انتقل إلى المحتوى"
  menuLabel="القائمة" navigationLabel="التنقل الرئيسي" externalLabel="يفتح في نافذة جديدة">
  <svg hwBrand viewBox="0 0 120 32" aria-hidden="true"><!-- brand artwork --></svg>
  <svg hwFooterBrand viewBox="0 0 120 32" aria-hidden="true"><!-- the same artwork for the footer --></svg>
  <h1>الخدمات</h1>
</hw-portal-layout>
```

The skip link is rendered as `#mainId` on the server and on the first client
render, and keeps resolving to the current document under any `<base href>` from
the reader's first interaction. `mainId` and `navigationId` are generated by the
application's `HwIdSource` when omitted, identically on the server and during
hydration; pass explicit values when markup or tests depend on them.

Content projection: `[hwBrand]` for brand artwork in the header, `[hwFooterBrand]`
for brand artwork in the footer, `[hwPortalActions]` for header actions, `[hwPortalFooter]` for additional footer content, default for
main page content. `HwSecondaryNavComponent` is independently available with
`items` and the required `label`. It uses ordinary links with `aria-current`, not tab/menu roles.

Standalone `HwPortalHeaderComponent` requires `menuLabel` and `navigationLabel`,
takes the same `brand`, `brandLabel` and `homeHref`, and renders its skip link
only when `mainId` names a target, which then needs `skipLabel`. Standalone
`HwPortalFooterComponent` requires `externalLabel`; `navigationLabel`,
`legalLinksLabel` and `supportLabel` are required with `links`, `legalLinks` and
projected `[hwFooterSupport]` content, and its support section is shown only for
that content; without it the section stays in the document with the `hidden`
attribute, no heading and no name. `brandLabel` names projected `[hwFooterBrand]`
artwork or the brand text, and is written only while the brand block has either. Escape closes the mobile
disclosure and focuses its toggle; link selection, outside press and focus
leaving close it. Tab remains native and desktop links stay visible. Each header
gets a distinct navigation ID unless supplied explicitly. No vanilla controller
is attached to Angular-owned DOM.

The 48rem mobile breakpoint is a Hawiyah adaptation. Shared tokens support DGA,
Hawiyah and custom themes. No animation is added by this layout. Source-informed
composition does not establish exact visual parity or DGA certification.

## Mobile navigation bar

Use `variant="mobile"` on `SecondaryNav` (React/Vue) or `hw-secondary-nav`
(Angular). Items accept an optional decorative `icon` name from the bundled icon
stylesheet, such as `home-01`, `search-01` or `menu-01`; item labels and the
`label` of the navigation remain required.
Vanilla uses `data-variant="mobile"` and the same semantic HTML:

```html
<nav class="hw-secondary-nav" data-variant="mobile" aria-label="تنقل الجوال">
  <ul>
    <li><a href="/" aria-current="page"><span class="hw-icon" data-icon="home-01" aria-hidden="true"></span><span>الرئيسية</span></a></li>
    <li><a href="/services"><span class="hw-icon" data-icon="search-01" aria-hidden="true"></span><span>الخدمات</span></a></li>
  </ul>
</nav>
```

The bar uses equal-width items, 24 px icons, a 70 px minimum height, wrapped labels
and a top current-page indicator. It is in normal flow and does not cover page
content. Safe-area bottom padding accommodates mobile devices; the source OS
home indicator is not reproduced. The application owns route/current updates.
These are page links, not content tabs: preserve native Tab/Enter navigation.

DGA/custom color transitions use `--hw-duration-tab-bar: 300ms` and
`--hw-ease-tab-bar: cubic-bezier(0, 0, 0.58, 1)`. Hawiyah remains immediate by
default. Reduced motion removes transitions; forced colors retains the selected
top border and keyboard focus. Hover does not mark a route selected.

Source Mobile `8332:24202` → `8332:24242` → `8332:24282` supports color changes,
not a sliding indicator or tab-panel animation. Semantic colors adapt to theme;
icon color follows the label, since imported icon override endpoints were not
resolved. Arabic width differs from English in the source, so no fixed item
width is imposed. This is a source-informed composition, not certified parity.
