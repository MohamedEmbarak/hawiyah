# Public portal layout

Use the shared shell classes with semantic HTML. Header, secondary navigation,
breadcrumb, main container and footer are available without a page-specific
template. `enhance()` owns only marked vanilla trees. Navigation stays visible
without enhancement: do not put `hidden` or `data-open="false"` in initial HTML.

```html
<div class="hw-portal-layout" lang="ar" dir="rtl">
  <header class="hw-portal-header" data-hw="portal-header">
    <a class="hw-skip-link" href="#portal-content">انتقل إلى المحتوى</a>
    <a class="hw-portal-brand" href="/">هوية</a>
    <button class="hw-button hw-portal-menu-toggle" type="button" data-hw-portal-toggle>
      <span class="hw-icon" data-icon="menu-01" aria-hidden="true"></span>القائمة
    </button>
    <nav aria-label="التنقل الرئيسي" data-hw-portal-navigation>
      <ul><li><a href="/services" aria-current="page">الخدمات</a></li></ul>
    </nav>
  </header>
  <nav class="hw-secondary-nav" aria-label="التنقل الثانوي">
    <ul><li><a href="/services" aria-current="page">دليل الخدمات</a></li></ul>
  </nav>
  <main class="hw-portal-layout-main hw-container" id="portal-content" tabindex="-1">
    <nav class="hw-breadcrumb" aria-label="مسار التنقل"><ol>
      <li><a href="/">الرئيسية</a></li><li><span aria-current="page">الخدمات</span></li>
    </ol></nav>
    <h1>الخدمات</h1>
  </main>
  <footer class="hw-portal-footer"><strong>هوية</strong>
    <nav aria-label="روابط التذييل"><ul><li><a href="/privacy">الخصوصية</a></li></ul></nav>
  </footer>
</div>
```

```ts
import { enhance } from '@hawiyah/vanilla';
import '@hawiyah/styles/styles.css';
const dispose = enhance(document.querySelector('.hw-portal-layout')!);
// Dispose before replacing the shell.
```

For direct control, `createPortalHeader(header, { onOpenChange })` returns
`open`, `show()`, `close(restoreFocus?)` and `destroy()`. Escape closes the mobile
navigation and returns focus to its toggle. Selecting a link, moving focus out,
or pressing outside closes it; Tab retains native navigation. The desktop links
remain visible. IDs generated by enhancement are removed on cleanup, and the
original attributes are restored. Use distinct main IDs for multiple shells.

### Text is supplied by the application

The header prints no text of its own. Each name comes from the markup first, then
from a `data-hw-*` attribute on the header root, then from the controller option
of the same name, which wins. When a required name is missing nothing is written
and a development warning (`Hawiyah: PortalHeader requires "…"`) is logged once.

| Input | Attribute | Required | Used for |
| --- | --- | --- | --- |
| `menuLabel` | `data-hw-menu-label` | when the toggle has no text or `aria-label` | Name of the menu toggle shown at narrow widths. |
| `navigationLabel` | `data-hw-navigation-label` | when the navigation has no `aria-label` or `aria-labelledby` | Name of the primary navigation landmark. |
| `brandLabel` | `data-hw-brand-label` | no | `aria-label` of `.hw-portal-brand`, for a brand that is artwork alone. |

The brand is the application's content: text, artwork, or both, authored inside
`.hw-portal-brand`. Use a link only when there is a home destination. A brand
with visible text needs nothing more. An artwork-only brand is named by
`brandLabel`, by an `aria-label` already on the brand, or by an image with a
non-empty `alt`; otherwise a development warning asks for `brandLabel`. The
option overrides an authored `aria-label`; the attribute does not.

```html
<header class="hw-portal-header" data-hw="portal-header" data-hw-brand-label="هوية، الصفحة الرئيسية">
  <a class="hw-skip-link" href="#portal-content">انتقل إلى المحتوى</a>
  <a class="hw-portal-brand" href="/"><svg aria-hidden="true" viewBox="0 0 120 40">…</svg></a>
  …
</header>
```

The skip link text is required content of the link (`skipLabel` in the framework
adapters). `createPortalHeader` binds every `a.hw-skip-link` inside the header as a
packaged fragment link through `createSkipLink`; a skip link elsewhere is bound
with `data-hw="skip-link"` or `createSkipLink(link)`. The markup keeps
`href="#portal-content"`; on interaction the href resolves to the current
document under any `<base href>`, and a plain activation scrolls to the main
container without animation and moves focus to it. The footer brand line,
support section and link names are authored markup, so they follow the same
rule: render them only when the application has text for them.

Use a native `details[data-hw-portal-branch]` inside the navigation for a group of links.
The summary stays keyboard-operable before enhancement. A flat branch can contain a single
list. For a grouped panel, give each list a visible heading.

```html
<li>
  <details class="hw-portal-branch" data-hw-portal-branch>
    <summary>الخدمات</summary>
    <div class="hw-portal-branch-panel">
      <section class="hw-portal-branch-group">
        <h2>التراخيص</h2>
        <ul>
          <li><a href="/licenses/new" aria-current="page">إصدار ترخيص</a></li>
          <li><a href="/licenses/renew">تجديد ترخيص</a></li>
        </ul>
      </section>
    </div>
  </details>
</li>
```

Opening a sibling summary closes the previous branch. Escape closes the innermost open
branch and focuses its summary. A subsequent Escape closes the mobile navigation when
its toggle is expanded. Moving focus or pressing outside a branch dismisses it. Links
retain their native activation. Set `aria-current="page"` on the destination selected by
your router. Group order, labels, URL normalization and any optional artwork belong to
the host application.

The NIC reference emits flat link lists and grouped columns in `master.js` lines 733–765
and handles outside clicks and mobile toggles in lines 873–925. Its site-specific IDs,
session storage and remote image URLs are unnecessary for this composition. Use artwork
with redistribution terms appropriate to your application. [NIC reference and provenance](../../docs/nic-web-reference.md)

The 48rem mobile disclosure breakpoint is a Hawiyah adaptation. The source audit
supports the header/navigation/footer composition; this is not a claim of exact
pixel or official certification parity. Set `lang="en" dir="ltr"` and translate
all labels for English; direction remains independent from language. All themes
use semantic tokens. The layout itself adds no animations.

## Mobile navigation bar

Use `variant="mobile"` on `SecondaryNav` (React/Vue) or `hw-secondary-nav`
(Angular). Items accept an optional decorative `icon` name from the bundled icon
stylesheet, such as `home-01`, `search-01` or `menu-01`; labels remain required.
Vanilla uses `data-variant="mobile"` and the same semantic HTML:

```html
<nav class="hw-secondary-nav" data-variant="mobile" aria-label="تنقل الجوال">
  <ul>
    <li><a href="/" aria-current="page"><span class="hw-icon" data-icon="home-01" aria-hidden="true"></span><span>الرئيسية</span></a></li>
    <li><a href="/services"><span class="hw-icon" data-icon="search-01" aria-hidden="true"></span><span>الخدمات</span></a></li>
  </ul>
</nav>
```

The bar uses equal-width items, 24 px icons, a 70 px minimum height, wrapped labels
and a top current-page indicator. It is in normal flow and does not cover page
content. Safe-area bottom padding accommodates mobile devices; the source OS
home indicator is not reproduced. The application owns route/current updates.
These are page links, not content tabs: preserve native Tab/Enter navigation.

DGA/custom color transitions use `--hw-duration-tab-bar: 300ms` and
`--hw-ease-tab-bar: cubic-bezier(0, 0, 0.58, 1)`. Hawiyah remains immediate by
default. Reduced motion removes transitions; forced colors retains the selected
top border and keyboard focus. Hover does not mark a route selected.

Source Mobile `8332:24202` → `8332:24242` → `8332:24282` supports color changes,
not a sliding indicator or tab-panel animation. Semantic colors adapt to theme;
icon color follows the label, since imported icon override endpoints were not
resolved. Arabic width differs from English in the source, so no fixed item
width is imposed. This is a source-informed composition, not certified parity.
