The independent idea panel was cut to save usage. This shortlist is mine, drawn from what the auditors recorded as worth keeping and from the gaps they measured.

Cost S to M

Controls on every example for language, direction, mode and density

Problem. Independent locale and direction is one of the library's distinguishing properties, yet the only way to set direction apart from language today is a select on the foundations page that changes the whole guide.

Idea. A small toolbar on each live example sets the four attributes on that example only, using package components.

Cost S

Install path chooser on the landing page

Problem. Framework articles have no install step and open with commands that only work in a clone. The JavaScript path needs a bundler and does not say so.

Idea. Choose framework and package manager; get the exact commands, the one import line, and a first component, generated from the pinned version.

Cost M

Evidence panel per component

Problem. The repository records verification evidence per component and adapter, but the guide shows almost none of it, and the catalogue's verified flags omit 53 tested pairs.

Idea. Each component page lists what is verified in which adapter, by which test, and what is open. Generated from components.json. It states evidence and makes no claim beyond it.

Cost S once the API check exists

Adapter parity table

Problem. Readers cannot tell which props exist in which adapter; this audit found 115 P1 parity gaps.

Idea. A generated page showing, per component, which API exists in each adapter. It doubles as the maintainer's worklist.

Cost M

Recipes by task in place of the journeys

Problem. The discover and apply journeys duplicate three templates and are built from guide-only copies of components.

Idea. A short set of task recipes (a validated form, a service page, a results list), each a template built from package components with a downloadable project.

Cost S to M

Shareable editor links

Problem. Editor drafts are lost on a route change, a language switch or a reload, and a bug report cannot point at a reproduction.

Idea. Encode the editor state in the link. Issue templates ask for one.

Cost M

Keyboard notes you can try

Problem. Keyboard behaviour is the part of each component that matched best across adapters, and the guide does not show it.

Idea. Each interactive component page lists its keys from the Markdown accessibility section, next to the live example, with the same list driving an automated test.

Cost M to L, needs a release decision

Starter projects

Problem. The download project is the only real-install path, has no Angular CLI variant, and is not type-checked.

Idea. First, fix and test the downloads for four frameworks. Later, if wanted, a create package; that is a new published package and needs your approval.
